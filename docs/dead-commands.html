Dead & blocked commands

Half the CS2 config advice online is a CS:GO config with a new title. This page lists commands that do not work in current CS2, each one checked in the console, with the exact message the game prints back.

See what is gone Convar reference

00 Check it yourself, in ten seconds

Type the bare name into the developer console. There are only three possible answers, and they tell you everything:

Console printsMeaning
Unknown command: xIt does not exist in current CS2. The line is dead weight in a config and can be deleted.
"x" = "value" plus a descriptionIt exists. Whether you may change it is a separate question; see blocked.
usage: x <arg>It exists and it is a command, not a convar, so it wants an argument. See wrong usage.

To capture a batch of answers instead of squinting at the console, add -condebug to your launch options; add -conclearlog after it to wipe the file each launch. Output lands in game\csgo\console.log.

One catch. The log captures Unknown command lines, exec traces, bind translations and command usage lines, but not convar values, not echo output and not help output. That makes it an exact record of what does not exist: run a batch of names, and any name that never appears in the log exists. For reading values, read the console itself.

find <text> is the other half of it: the search covers command names and their descriptions, so find crosshair lists what your build offers instead of what a 2019 guide remembers.

One exception to the three answers. A few names are rejected by the console yet still read while the game starts, so they work as a +name value launch option. Unknown command rules out the console, not the launch path. See startup-only convars.

02 Blocked: it exists, the engine refuses

Worse than a dead command, because the name resolves and the guide looks right. The engine declines the write, and it tells you so.

CommandWhat happens
cl_interp 
Cannot change the value of cl_interp.  Please remove this command from your script
cl_interp = 0.000000 (cl_interp_ratio=0 / cl_updaterate=64)
CS2 derives interpolation from cl_interp_ratio and cl_updaterate and owns the result. The old CS:GO habit of pinning cl_interp 0.015625 buys you an error message on every launch. Delete it.

The other blocked class is cheat and replicated convars: sv_cheats-flagged commands are refused on any server you do not control, and replicated ones are dictated by the server whatever your config says. help <name> prints the flags that decide this.

03 Renamed, not removed

The feature survived the move to Source 2, the name did not. Copying the CS:GO name gets you an Unknown command; the replacement does what you wanted.

CS:GOCS2Both sides verified
zoom_sensitivity_ratio_mousezoom_sensitivity_ratioyes; old name unknown, new name returns a value
fps_max_menufps_max_uiyes
bind_listkey_findbinding <substring>yes
cl_righthandswitchhands + cl_prefer_lefthandedyes

No replacement found is not the same as renamed. net_graph, voice_enable, con_filter_text and cl_disablefreezecam are gone here, and the "CS2 equivalents" posted around the web (cq_netgraph for the first one especially) came back Unknown command too. If a replacement turns up in the console, it gets added; guesses do not.

04 Startup-only: unknown in console, read at launch

A fourth answer that looks exactly like death: the name is rejected by the runtime console, but the engine still reads it while it is starting up. Typing it in-game proves nothing about whether setting it at launch does something.

NameIn the consoleAt launch
r_dynamic Unknown command, the same answer the genuinely dead names give Works when set at launch. +r_dynamic 0 in Steam's launch options is read while the game starts and the value holds. pending the effect is observed in game, not yet pinned to a line in console.log

This is why Unknown command alone is not proof. It says the name is not registered in the console at the moment you typed it. It does not say the engine never looks at that name. Anything you set through Steam's launch options is applied on a different path from the one the console uses.

The distinction matters for how you write a config: a startup-only convar cannot live in autoexec.cfg, because the autoexec is exec'd through the console and gets the same Unknown command. It belongs in the launch options, prefixed with +:

-condebug +r_dynamic 0

To check one yourself: launch with -condebug and the +name value option set, then read game\csgo\console.log. A name that never appears there as an unknown command was accepted at startup, whatever the console says about it later.

05 Commands vs convars

A usage line means the name exists. CS2 has two kinds of names and they answer differently: a convar holds a value and prints it, a command does something and takes arguments, so bare it prints how to call it.

Reference for the argument forms that are easy to get wrong:

usage: key_findbinding <substring> [splitscreen player]

Usage: incrementvar varName minValue maxValue delta

Usage: toggle varName [... optional list of valid values to cycle]

cl_ticktiming usage:
  cl_ticktiming print [summary|detail]   Print stats now.  Default detail level is 'detail'
  cl_ticktiming <N>   [summary|detail]   Print stats periodically, every N ticks.
                                         N=0 to disable.  Default detail level is 'summary'

cl_ticktiming needs print or a tick interval; bare it only describes itself. log_color is the same shape, taking a channel name and an RGBA value: log_color "Console" "FF25FFFF". Bare alias is the other one to remember: it dumps every alias currently defined, which is the quickest way to see whether a config loaded.

06 Contributing an entry

The bar for an entry is one console line, not a forum post: the command, and what CS2 printed back. Open an issue with that output and the date. Builds change, and an entry that has silently become wrong is worse than no entry at all.
