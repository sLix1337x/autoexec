Part I · General reference

Everything below applies to any CS2 config, not just this one.

Every command named on these pages was typed into a live CS2 console and answered. If it is listed without a badge, the console returned a value or a usage line. Anything still untested carries a pending badge, and anything that answered Unknown command was moved to dead & blocked commands. The page is incomplete on purpose rather than confidently wrong, and it grows as things get checked.

01 Where CS2 configs live

CS2 splits configuration across two different trees, and the split is the source of most "my settings reset" confusion.

The install folder: files you write

...\Steam\steamapps\common\Counter-Strike Global Offensive\game\csgo\cfg\

This is where autoexec.cfg and any hand-written .cfg goes. exec resolves paths relative to this folder, so exec core/keys loads cfg\core\keys.cfg. Subfolders are fine, the .cfg extension is optional in the command.

The userdata folder: files the game writes

...\Steam\userdata\<SteamID3>\730\local\cfg\
cs2_user_convars_0_slot0.vcfgyour saved convars (sensitivity, crosshair, volume, HUD…), anything menu-facing that carries the archive flag
cs2_user_keys_0_slot0.vcfgyour saved key binds
cs2_machine_convars.vcfgmachine-wide settings, not tied to the Steam account
cs2_video.txtvideo settings: resolution, aspect, quality presets

CS2 no longer uses CS:GO's config.cfg. These .vcfg files are written by the game when you change something in the menu and on shutdown; editing them by hand is a losing game.

Startup order, read out of a real console.log:

Saved 'cs2_user_keys.vcfg' to SteamRemoteStorage, 1185 bytes OK
Saved user config file 'cfg/cs2_user_keys_0_slot0.vcfg'
Saved user config file 'cfg/cs2_user_convars_0_slot0.vcfg'
execing autoexec.cfg
  execing core/load ... your own exec chain
[later, on map load]
execing gamemode_competitive.cfg
execing gamemode_competitive_offline.cfg
execing server_default.cfg

That settles three things. The .vcfg files are written and pushed to Steam Cloud before your config runs; autoexec.cfg then runs and overrides them for the session, which is exactly why a value pinned in autoexec appears to "not save" when you change it in the menu; and the game execs several more configs later, on map load.

Those late ones are usable hooks of their own: gamemode_competitive.cfg runs when a competitive match loads, server_default.cfg when you host. A missing one is not an error: the log says exec: couldn't exec '{*}cfg/gamemode_competitive_server.cfg', unable to read file and moves on.

Steam Cloud can also restore an older copy of these files over yours. If configs keep reverting after a restart, disable cloud sync for CS2 in Properties → General and re-check.

02 An autoexec that actually loads

  1. Create autoexec.cfg in the install cfg\ folder. Save as All files so it doesn't end up autoexec.cfg.txt; plain UTF-8 or ANSI, no BOM needed.
  2. One command per line. Console-style chaining with ; works, but line-per-command is what you want to read at 2am.
  3. Nothing else is required. CS2 execs autoexec.cfg from that folder at startup on its own, verified on a client whose only launch option was -condebug and whose log still shows execing autoexec.cfg. To re-run it mid-session, type exec autoexec.
  4. End the file with a marker so you can see it ran: 
    echo "=== autoexec loaded ==="
    Open the console after launch and look for the line. echo output does not reach console.log even with -condebug, but the execing autoexec.cfg trace does, which answers the same question.

+exec autoexec is a fallback, not a requirement. Most guides present it as mandatory; a client with no +exec at all still execs the file. Add it only if your marker never appears; then it forces the exec explicitly. The flag actually worth having is a different one, -condebug, which writes everything the console prints to game\csgo\console.log and makes all of this debuggable at all.

Splitting a config across files

Anything past a few dozen lines is easier as one loader plus modules:

// autoexec.cfg
exec cfg/settings      // convars only
exec cfg/aliases       // behaviour
exec cfg/binds         // keys last, so nothing overwrites them

Order matters: aliases must exist before a bind points at them, and binds should run last so a later file can't silently steal a key.

Read-only is a trap. Marking autoexec.cfg read-only is harmless, but marking the .vcfg files read-only to "lock" settings stops the game writing anything, including new settings you actually want, and it breaks after updates that rename convars. Use autoexec to pin values instead.

03 Config syntax

FormMeaning
cvar valueset a convar. Quotes optional for simple values, required if the value contains spaces
cvaralone in the console prints its current value, as in cl_crosshairgap = -5. A command typed bare prints its usage line instead, and a name that doesn't exist prints Unknown command
// textcomment to end of line. There is no block comment
a; b; ccommand separator, the whole line runs in order
"a; b"quoted compound, used as the body of a bind or alias
exec filerun another cfg, path relative to cfg\, extension optional
echo textprint a simple marker or message to the console while debugging
toggle varName [values…]step a convar through a list of values. Usage: "toggle varName [... optional list of valid values to cycle]"
incrementvar varName min max deltastep a numeric convar, wrapping at the ends. Negative delta counts down

Quoting rule of thumb: one level of quotes per level of nesting is all the parser reliably gives you. bind x "alias_name" is fine; deeply nested quotes inside a bind inside an alias is where configs break. Push the complexity into a named alias instead of nesting.

Semicolons and the console

A line pasted into the console and the same line in a cfg behave identically, with one exception: the console only takes one line, so a multi-line block has to become a ; chain or an exec. This is why "run it in console to test, then paste into the cfg" is the fastest way to iterate.

Scancode binds are the fix for non-US layouts: bind scancode53 … hits the physical key left of 1 no matter what character your layout prints there. To find any key's number, bind it by name and read the line CS2 echoes back:

> bind w +forward
Interpreting bind command as:
    bind scancode26 "+forward" // US English key name "w"

Full list on the scancode table page.

Hold vs press

Commands starting with + are hold commands: pressing the key fires +x, releasing fires -x automatically. That pairing is the whole basis of movement scripts.

bind mouse1 "+attack"           // held while the button is down
bind space  "+jump"
bind mwheeldown "+jump"          // press and release both fire on one scroll tick

Mouse wheel is a special case: a scroll produces a press and release in the same instant, which is why it works for bhop but not for anything needing a real hold.

05 Aliases, toggles and state

alias name "commands" defines a named command. Aliases are where a config stops being a settings list and starts being a small program.

Indirection layer

alias drop_bomb "slot5; drop; slot1"
bind g drop_bomb

Bind keys to verbs, never to raw commands. Change the verb once and every key bound to it follows, and you can rebind a key without re-reading what it did.

Hold aliases

alias +quickswitch "slot3"
alias -quickswitch "lastinv"
bind kp_6 +quickswitch

A +/- alias pair turns any key into a hold action: knife out while held, previous weapon on release.

The flip-flop, a two-state toggle

alias radar_toggle radar_big
alias radar_big   "cl_hud_radar_scale 1.30; alias radar_toggle radar_small"
alias radar_small "cl_hud_radar_scale 0.80; alias radar_toggle radar_big"
bind n radar_toggle

An alias that redefines itself is the standard CS toggle. Each call does its work and rewrites the entry point to point at the other half. Extend the chain and you get a cycle of any length: seven crosshair presets, eight viewmodel positions, three movement modes are all this pattern.

Cheaper cycles

bind kp_7 "incrementvar cl_crosshairsize 1 6 1"   // step and wrap
bind kp_8 "toggle cl_crosshairdot 0 1"           // step through a value list

If the state is a single convar, toggle/incrementvar replaces the whole alias chain. Use aliases only when a step has to change several things at once.

State machines with exec

Aliases can be redefined by an exec, so a folder of tiny cfg files becomes a state machine: each file sets the aliases for one state and defines how to enter the next. This is how null-bind configs keep per-axis state without any real variables, and how the movement module in this repo works.

Aliases do not persist. They live only in the current session. Anything you define must be defined again by autoexec on every launch. Nothing is written to the .vcfg files.

06 Recipes

Null-binds / SOCD

"Opposite key priority": when A and D are both held, decide what happens instead of letting the last input win. Each direction gets a wrapper that remembers whether its opposite is down.

alias +mfwd "-back; +forward; alias checkfwd +forward"
alias -mfwd "-forward; checkback;  alias checkfwd none"
alias +mback "-forward; +back; alias checkback +back"
alias -mback "-back; checkfwd;   alias checkback none"
alias checkfwd  none
alias checkback none
alias none ""
bind w +mfwd
bind s +mback

Same shape for A/D. Three behaviours: null (both held = stand still), last-input-wins (the newest key moves you), and raw (stock engine behaviour). Valve has left these working; SOCD handling at hardware level is what gets banned in tournaments, not the cfg version.

Jump throw

alias +jumpthrow "+jump; -attack; -attack2"
alias -jumpthrow "-jump"
bind t +jumpthrow

Still functions, but CS2's subtick input makes it far less deterministic than the CS:GO version, and several leagues ban multi-action binds. Grenade lineups are the same on any server since subtick removed tick-rate variance.

Fast drop / bomb drop

alias dropbomb "slot5; drop; slot1"
bind ` dropbomb

Hold to zoom the radar out

alias +radar "cl_hud_radar_scale 0.70"
alias -radar "cl_hud_radar_scale 0.35"
bind m +radar

Step a convar instead of scripting it

bind n "incrementvar cl_radar_scale 0 1 0.25"

Four radar zoom levels on one key, no aliases at all.

Clutch mute

alias clutch_toggle clutch_on
alias clutch_on  "voice_modenable 0; alias clutch_toggle clutch_off; echo [MUTED]"
alias clutch_off "voice_modenable 1; alias clutch_toggle clutch_on;  echo [UNMUTED]"
bind f8 clutch_toggle

Every guide writes this with voice_enable, which does not exist in CS2. voice_modenable does.

Two things you cannot script here. There is no buy console command: buy binds are not a thing in CS2, the buy menu is the interface. And the "display damage" console filter is gone with the whole con_filter_* family. See dead & blocked commands.

07 Convar reference

The convars worth putting in a config, grouped by what they touch. Defaults and limits below are the ones help reports; "no limits" means the convar declares none, not that the check was skipped.

Reading help output

help <name> is the authority on all of this, and it answers in a single line:

help viewmodel_fov
viewmodel_fov = 68 (default 60, min 60, max 68) [client archive userinfo per_user] - Viewmodel FOV

Current value, then defaults and limits in parentheses (empty parentheses mean none are declared), then flags in brackets, then the description. The flags are the part to learn:

FlagWhat it means for a config
archivesaved to the .vcfg files and restored on launch
per_userstored against the Steam account rather than the machine
userinfosent to the server as part of client info
cheatneeds sv_cheats 1, so it only applies on a server you control
replicatedthe server dictates it; a config value is ignored in a match
notifychanging it announces itself to players
client / gamewhich side owns it

This is how to tell in advance whether a line will do anything on an official server. cl_showpos, for instance, is flagged cheat, so it is not a HUD option you can switch on in matchmaking.

09 Limits, gotchas & safety

Configs are not a ruleset

A cfg only issues commands the game exposes; it cannot replace external input software. That does not guarantee every bind is allowed everywhere: VAC, official-server restrictions and tournament rules are separate questions.

Tournament rules are stricter

Rules vary by event and can change. Multi-action binds such as jump-throw, run-boost or quickswitch scripts may be restricted, so check the current ruleset before relying on one.

Aliases die on exit

No alias is ever saved. If it isn't in a file that autoexec runs, it doesn't exist next launch.

Autoexec beats the menu

Any convar pinned in autoexec is re-applied on every launch, silently undoing menu changes. Pin only what you never tune from the menu.

CS:GO configs don't transfer

Many CS:GO convars were removed or renamed: for example net_graph, m_rawinput and parts of the cl_bob* family. Review an old config line by line; unknown commands are reported and skipped, but surviving commands can still change your setup.

Some convars are locked

Cheat-flagged, replicated or server-owned convars refuse to change on servers you do not control. help <name> prints the flags in brackets, so you can tell before you write the line. See reading help output.

Read configs before running them

A downloaded cfg can unbindall, rebind your keys or run an exec you didn't expect. Read it first: it can wreck a setup you spent hours on, even though a cfg cannot run arbitrary external programs by itself.

Updates break configs

Convars get renamed or removed each patch. When something stops working after an update, type the bare name in the console: Unknown command means it was removed, not that your config is broken.

10 Debugging a config

SymptomCheck
Nothing loadsFile is autoexec.cfg.txt, or it's in the userdata cfg folder instead of the install one. End the file with echo and watch for it.
Autoexec does not appear to loadFirst check the filename, install cfg\ folder and an echo marker. CS2 normally loads autoexec.cfg without a launch option; if the marker is still missing, try +exec autoexec in Steam launch options or run exec autoexec manually.
A cfg is missingNot silent. The log names it: exec: couldn't exec '{*}cfg/<name>.cfg', unable to read file. Check the path is relative to cfg\.
Half loadsPut an alias v_<name> "" marker at the top of every module and a diag file that calls each in load order. The first Unknown command names the file that never ran.
A key does nothingkey_findbinding jump, for example, shows what still owns the action. Something bound later usually took the key; binds must come last.
A convar won't changehelp <name> and read the flags. cheat needs sv_cheats; replicated means the server decides. cl_interp is refused everywhere regardless.
Movement stuckA + command latched without its -. Fire the release manually (-forward, -attack) or rebind the key to the stock command.
Settings revert after restartAutoexec is pinning them, or Steam Cloud restored an older .vcfg.

What -condebug logs, and what it doesn't. console.log captures Unknown command lines, exec traces, bind translations and command usage lines. It does not capture convar value echoes, echo output, or help output; those go to the console window only. So the log is an exact record of what failed and what ran, and no help at all for reading values.

Keep a two-line panic bind in every config that touches movement: bind kp_0 "-forward;-back;-left;-right;-jump;-duck;-attack". It costs one key and saves a round.

Part II · This repo's config

A worked example of the ideas above. CS2 Advanced Config is a modular autoexec: null-bind movement with three switchable modes, every key routed through named verbs.

12 Install

  1. Download the CS2 Advanced Config folder from the repo.
  2. Copy its contents into 
    ...\Counter-Strike Global Offensive\game\csgo\cfg\
    so that autoexec.cfg and the core\ folder sit directly in cfg\.
  3. Launch CS2. The file normally runs automatically. For an immediate test, run exec autoexec in the developer console. If automatic loading fails, add +exec autoexec to Steam launch options as a fallback.
  4. Watch the console for the CONFIGURATION LOADED SUCCESSFULLY banner. If it doesn't show, see Troubleshooting.

Launch options

No launch option is required for this config. Add +exec autoexec only if CS2 does not discover the file normally; treat performance flags as separate, hardware- and build-dependent troubleshooting.

13 Structure

The config is split by responsibility so any one piece can be read, changed, or diagnosed on its own.

CS2 Advanced Config/
├── autoexec.cfg              settings only — mouse, HUD, crosshair defaults,
│                              viewmodel, audio, network, performance
└── core/
    ├── load.cfg               the ONLY place that defines load order
    ├── reg.cfg                the verb layer: +slx_* aliases every key binds to
    ├── keys.cfg                every bind — points at verbs, never at raw game commands
    ├── diag.cfg                exec core/diag — finds which layer failed to load
    ├── help.cfg                exec core/help — prints the key map (bound to F11)
    └── modules/
        ├── movement.cfg        null-bind state machine, 3 modes
        ├── hud.cfg              radar boost, movement-mode HUD colour
        ├── crosshair.cfg        7 presets on a shared cycle key
        ├── viewmodel.cfg        8 positions on a shared cycle key
        └── weapons.cfg          fast bomb/gun drop, knife quickswitch

Binds never call a game command directly. They call a +slx_* verb declared once in reg.cfg. Change what a verb does in one place and every key bound to it follows.

14 Movement & null-binds

SOCD (opposite keys held at once) is resolved by a small state machine per axis instead of leaving it to CS2's own key handling. Three modes are one press apart on KP_4:

Null

Holding both A+D (or W+S) locks the axis at neutral: no movement on that axis until one key is released. The standard competitive null-bind behaviour.

Strict

Releasing either key of an opposing pair returns straight to neutral, rather than resuming movement in the direction of the key still held.

Raw

Reproduces stock CS2: both keys held is a dead stop, same as vanilla binds. Included as a clean fallback / A-B reference.

KP_5 is the master switch: null-binds entirely on/off, dropping straight back to stock +forward/+left/+back/+right binds when off.

Movement mode is mirrored on the HUD accent colour (toggle with KP_1): light blue = null, purple = strict, yellow = raw, grey = off.

19 Troubleshooting this config

Movement feels stuck

Tap KP_0 repeatedly; each press clears one latched input (strafe axis, forward axis, jump, duck, sprint, use). Six presses covers all of them.

Config didn't load

Open console and run exec core/diag. It calls a marker in every layer in load order, and the first Unknown command: v_<name> names the file that never ran; everything after it is meaningless.

Total reset

In console: bind w +forward; bind a +left; bind s +back; bind d +right restores plain stock movement regardless of what state the config is in.

Nothing happens on a keypad key

Run key_findbinding slx. If the verb isn't on the key, another config loaded after this one took it. keys.cfg must run last.
