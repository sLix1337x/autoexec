CS2 Advanced Config

A modular autoexec for Counter-Strike 2 — tuned settings, null-bind movement with three switchable modes, and every key routed through named verbs instead of hardcoded binds.

01 Install

  1. Download the CS2 Advanced Config folder from the repo.
  2. Copy its contents into 
    ...\Counter-Strike Global Offensive\game\csgo\cfg\
    so that autoexec.cfg and the core\ folder sit directly in cfg\.
  3. Launch CS2. In the developer console, run: 
    exec autoexec
    or add +exec autoexec.cfg to your launch options to load it every start.
  4. Watch the console for the CONFIGURATION LOADED SUCCESSFULLY banner. If it doesn't show, see Troubleshooting.

Recommended launch options

-threads 9 -noreflex — adjust thread count to your CPU's core count.

02 Structure

The config is split by responsibility so any one piece can be read, changed, or diagnosed on its own.

CS2 Advanced Config/
├── autoexec.cfg              settings only — mouse, HUD, crosshair defaults,
│                              viewmodel, audio, network, performance
└── core/
    ├── load.cfg               the ONLY place that defines load order
    ├── reg.cfg                the verb layer: +slx_* aliases every key binds to
    ├── keys.cfg                every bind — points at verbs, never at raw game commands
    ├── diag.cfg                exec core/diag — finds which layer failed to load
    ├── help.cfg                exec core/help — prints the key map (bound to F11)
    └── modules/
        ├── movement.cfg        null-bind state machine, 3 modes
        ├── hud.cfg              radar boost, movement-mode HUD colour
        ├── crosshair.cfg        7 presets on a shared cycle key
        ├── viewmodel.cfg        8 positions on a shared cycle key
        └── weapons.cfg          fast bomb/gun drop, knife quickswitch

Binds never call a game command directly — they call a +slx_* verb declared once in reg.cfg. Change what a verb does in one place and every key bound to it follows.

03 Movement & null-binds

SOCD (opposite keys held at once) is resolved by a small state machine per axis instead of leaving it to CS2's own key handling. Three modes are one press apart on KP_4:

Null

Holding both A+D (or W+S) locks the axis at neutral — no movement on that axis until one key is released. The standard competitive null-bind behaviour.

Strict

Releasing either key of an opposing pair returns straight to neutral, rather than resuming movement in the direction of the key still held.

Raw

Reproduces stock CS2: both keys held is a dead stop, same as vanilla binds. Included as a clean fallback / A-B reference.

KP_5 is the master switch — null-binds entirely on/off, dropping straight back to stock +forward/+left/+back/+right binds when off.

Movement mode is mirrored on the HUD accent colour (toggle with KP_1): light blue = null, purple = strict, yellow = raw, grey = off.

07 HUD & feel

Movement-mode colour

HUD accent repaints on every mode change: blue (null), purple (strict), yellow (raw), grey (off). Toggle with KP_1 — turning it back on catches up on the next mode change, it doesn't repaint instantly.

Radar boost

Hold M to zoom the radar out (0.70), release to snap back to the tight default (0.35).

Prediction off

Body/head-shot FX, ragdolls, weapon drop and bomb defusal all wait for server confirmation rather than playing client-side early.

Performance

fps_max 500, death cam skipped, tutorial pop-ups and tracers off.

08 Troubleshooting

Movement feels stuck

Tap KP_0 repeatedly — each press clears one latched input (strafe axis, forward axis, jump, duck, sprint, use). Six presses covers all of them.

Config didn't load

Open console and run exec core/diag. It calls a marker in every layer in load order — the first Unknown command: v_<name> names the file that never ran; everything after it is meaningless.

Total reset

In console: bind w +forward; bind a +left; bind s +back; bind d +right restores plain stock movement regardless of what state the config is in.

Nothing happens on a keypad key

Check bind_list hasn't been overwritten by another config loaded after this one — keys.cfg must run last.
