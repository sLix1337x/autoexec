Scancode table

Binding by scancode binds the physical key, not the character your layout prints on it. The full table is below, with how CS2 numbers them and how to read any key's number out of the console in one line.

01 Why bind by scancode

A key name is a character: bind w +forward means "whatever key produces w on the active layout". A scancode is a position: bind scancode26 +forward means "the key one row up and one right of caps lock", regardless of layout.

Layouts stop mattering

On QWERTZ the y and z keys swap places; on AZERTY the whole left block moves. A name-based config lands on the wrong physical keys. A scancode config doesn't move.

Layout switching stops breaking things

If you switch OS input language while the game runs, name binds follow the new layout. Scancode binds stay where your fingers are.

Punctuation keys become unambiguous

The key left of 1 is `, ^, ² or < depending on where you live, but it is always scancode53.

It is what CS2 stores anyway

Bind by name and the game translates to a scancode immediately, then echoes the translation. You are writing the same bind either way; one form survives contact with another keyboard.

The numbering is not Valve's. CS2 scancode numbers are USB HID keyboard usage IDs (HID usage page 0x07), the codes the keyboard itself sends. That is why a is 4 rather than 1: the first four IDs on that page are reserved for error states.

02 Find any key's scancode

Bind the key by its name and let the game tell you. CS2 prints the translation every time it interprets a name-based bind:

> bind w +forward
Interpreting bind command as:
    bind scancode26 "+forward" // US English key name "w"

That comment is the answer: w is scancode26. It works for any key, including ones your layout can't type: bind those from the in-game settings menu and watch the same line appear.

To collect a batch, add -condebug to launch options and read game\csgo\console.log in a text editor afterwards; every Interpreting bind command as line is in there. Add -conclearlog after it to start each session with an empty file.

CS2 tells you when your layout is the problem

On a non-US layout the console adds a second suggestion of its own whenever the requested character sits somewhere else physically:

If the binding doesn't work and you're not using a US English keyboard, you should try:
    bind scancode29 "sc_x" // US English key name "z"
Interpreting bind command as:
    bind scancode28 "sc_x" // US English key name "y"

That is a QWERTZ board being told that its y key is physically the US z key. The same hint appears for punctuation whose position moves. When you see it, the scancode in the hint is usually the one you actually want.

Both forms work in a config, and the scancode form is the one that keeps working:

bind w          "+slx_forward"   // breaks on a different layout
bind scancode26 "+slx_forward"   // binds the physical key, always

04 What has no scancode

Scancodes are a keyboard numbering, and CS2 confirms it by staying silent: binding MOUSE1–MOUSE5, MWHEELUP or MWHEELDOWN produces no Interpreting bind command as line at all, because there is nothing to translate. Mouse inputs keep their names:

InputBind as
Mouse buttonsMOUSE1–MOUSE5
Mouse wheelMWHEELUP, MWHEELDOWN
Extra mouse buttons past 5usually not seen by the game. Map them to a key in the mouse software, then bind that key's scancode

Mixing forms in one config is fine and normal: mouse by name, keyboard by scancode.

bind mouse1     "+attack"
bind scancode26 "+slx_forward"
